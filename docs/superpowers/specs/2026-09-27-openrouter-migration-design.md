# OpenRouter Migration & Dependency Refresh — Design

Date: 2026-09-27

## Goals

1. Use current, compatible package versions, managed with uv in a project-scoped `.venv`.
2. Replace the OpenAI / Anthropic / Gemini providers with OpenRouter only. The model list is fetched live from
   OpenRouter's `/api/v1/models` endpoint, filtered to sensible candidates, and labelled with price and an
   estimated cost for the uploaded book so users don't pick an expensive model by accident.

## Non-goals

- Changing the pre-read prompt, `ChapterDigest` schema, or EPUB insertion format.
- Persisting API keys or results.

## Architecture

| Unit | Responsibility | Depends on |
|---|---|---|
| `openrouter_models.py` (new) | Fetch catalog, filter models, estimate cost, format labels. Pure functions except `fetch_models`. No Streamlit import. | `httpx` |
| `summarize_epub_streamlit.py` | Streamlit UI, EPUB extraction/insertion, concurrent summarization via pydantic-ai. | `openrouter_models`, `pydantic-ai-slim[openrouter]`, `ebooklib`, `bs4` |
| `tests/test_openrouter_models.py` (new) | Unit tests for filter and cost logic against a JSON fixture. | `pytest` |

Removed: provider dict, per-model tier tables, custom RPM/TPM, buffer selector, batch-size/wait calculation,
`on_provider_change` / `on_model_change`.

## LLM calls

- `pydantic_ai.Agent(OpenRouterModel(model_id, provider=OpenRouterProvider(api_key=key)), output_type=ChapterDigest)`.
- The API key is passed directly, not via `os.environ`, so it doesn't leak across Streamlit sessions.

## Model catalog & filtering

- `fetch_models()` does `GET https://openrouter.ai/api/v1/models`, needs no key, and returns `data`.
- The UI wraps it in `st.cache_data(ttl=3600)` and adds a "Refresh model list" button that clears the cache.
- If the fetch fails, the UI shows an error and a free-text model-ID input.

A model is kept when **all** of these hold:

- `"text"` is in both `architecture.input_modalities` and `output_modalities`, and `output_modalities` contains
  only `"text"` (this excludes image/audio generation models).
- `supported_parameters` contains `structured_outputs` or `tools`.
- `pricing.prompt` and `pricing.completion` parse as floats ≥ 0 (routers use `-1` and are excluded).
- The id doesn't end with `:batch` and doesn't start with `~`.
- `expiration_date` is null or later than today.
- `context_length` ≥ `min_context`, where `min_context = chars_per_chapter/4 + 450 (prompt) + 2000 (output headroom)`.
- The input price per million is ≤ `max_input_price` (slider: $0.10–$20.00, default $1.00).
- The id ends with `:free` only when `include_free=True`. Otherwise free models are excluded.

The list is sorted by input price, then output price, then id.

## Cost estimate

- `CHARS_PER_TOKEN = 4`, `PROMPT_OVERHEAD_TOKENS = 450`, `OUTPUT_TOKENS_PER_CHAPTER = 700`.
- `estimate_cost(model, char_counts, chars_per_chapter)` returns USD:
  sum over chapters of `(min(c, limit)/4 + 450) * prompt_price + 700 * completion_price`.
- The dropdown label is `"{id} — ${in:.2f}/${out:.2f} per M — est. ${cost:.2f}"`. It uses 3 significant decimals
  when the cost is under $0.01. The estimate covers the selected chapters, or all extractable chapters when none
  are selected yet, or one chapter at `chars_per_chapter` before any upload.
- After a run, the actual cost comes from the summed `result.usage()` input/output tokens × catalog prices.
  It's shown alongside the result.
- The UI notes that reasoning models may exceed the output estimate.

## Free models

- An "Include free models" checkbox is off by default.
- When a `:free` model is selected, the UI warns about roughly 20 requests/min and a daily request cap, and
  concurrency is forced to 1.

## Throughput & errors

- A "Parallel requests" slider (1–16, default 4) controls an `asyncio.Semaphore`, and all chapters run through
  `asyncio.gather`.
- Each chapter gets up to 4 attempts with exponential backoff (`2**attempt` s plus jitter, capped at 30 s).
  A 429 `Retry-After` header is honoured when present.
- 401 (bad key) and 402 (insufficient credits) are fatal. They cancel the run and show a clear message.
- Chapters under 800 characters are skipped, as today.
- A single status line and a progress bar update per completed chapter.

## Dependencies & environment

- `pyproject.toml`: `requires-python = ">=3.12"`. Direct deps only, with `>=` floors at current latest:
  `streamlit>=1.64`, `pydantic-ai-slim[openrouter]>=2.51`, `ebooklib>=0.20`, `beautifulsoup4>=4.15`, `lxml>=6.1`,
  `httpx`. There's a dev group with `pytest`.
- `uv.lock` is committed. `requirements.txt` is generated by `uv export --no-dev --no-hashes` for Streamlit Cloud.
- The local `.venv` is created by `uv sync` with Python 3.13 and is gitignored.
- The devcontainer image moves to Python 3.13 and installs from `requirements.txt`.
- The README is rewritten for OpenRouter (key at openrouter.ai/keys, pricing and filtering notes, concurrency),
  and the tier sections are removed.

## Verification

- `uv run pytest` covers the filter rules (each exclusion rule, sort order, free toggle, price cap, context floor)
  and the cost math.
- An import smoke test of the app module.
- Launch `uv run streamlit run summarize_epub_streamlit.py` and confirm in the browser that the model list loads
  with price labels and that the slider and free toggle change the list. An end-to-end summarization needs the
  user's OpenRouter key.
